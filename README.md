# WORK WATCH — табель рабочего времени

Веб-прототип графика смен: закреплённые столбцы, фильтр по отметкам легенды, блок **«Сводка»**, **«Расстановка по зонам»**, **«Отпуска»** (ВП + ОТ), **карта BLE-меток**, **архив** (месяцы с марта года вне трёх «живых» — только просмотр и выгрузка JSON), экспорт. Без сборки — только статические файлы.

## Руководство пользователя

Подробный гайд по всем функциям сайта (табель, вход, синхронизация, карта BLE, офлайн-фото): **[`USER_GUIDE.md`](USER_GUIDE.md)**.

## Запуск локально

Откройте в браузере файл [`index.html`](index.html) или поднимите любой статический сервер в корне репозитория.

## Актуализация графика из Excel (.xlsx)

Файл в формате как **«График работы на объектах»** (лист **«График 2026»**: колонки ТН, ФИО, затем дни подряд с января по июнь).

1. Один раз: **`npm install`**
2. Запуск (путь в кавычках, если есть пробелы):
   ```bash
   npm run ingest-xlsx -- "C:\Users\...\График работы на объектах.xlsx"
   ```
   По умолчанию выбирается лист с именем вроде **«График 2026»**; иначе задайте переменную **`TABEL_SHEET`** с точным именем листа.
3. Скрипт перезапишет **`scripts/parsed-employees-2026-h1.js`** (`PARSED_2026_1` … `PARSED_2026_6`). В **`app.js`** ключи **`2026-1`** … **`2026-6`** уже ссылаются на эти массивы; в **`index.html`** файл подключён перед **`app.js`**. Строки **без ТН** (номер появится позже) попадают в выгрузку по колонке ФИО; в поле ТН ставится **`—`**, пока в Excel не появится число — затем снова запустите импорт.
4. Закоммитьте и запушьте **`main`**, чтобы обновился GitHub Pages.

Выгрузка **CSV** из Google Таблицы по-прежнему обрабатывается **`scripts/parse-tabel-csv.mjs`** (для одного месяца в отдельный `.js`; для января–июня из книги Excel используйте **`ingest-xlsx`**).

## Синхронизация из Google Таблицы (кнопка, только админ)

Основная книга: [график в Google Sheets](https://docs.google.com/spreadsheets/d/1h-GMxdT2z3MC-somIq8sX3iV6KfjaoCffIIfeBQezRk/edit?gid=1225208192) (лист `gid=1225208192`).

- **B** — объект (аббревиатура), **C** — полное название, **D** — ТН, **E** — ФИО, **F** и далее — дни (в строке 1 — месяцы; **F** = 1-е января).
- В меню под **«Админ»** → **«Синхронизировать из Google»** (только загрузка в табель, без обратной записи в таблицу).
- Перед синхронизацией на этом устройстве сохраняется копия для **«Откатить синхронизацию Google»**.
- Таблица должна быть доступна по ссылке (**просмотр** для всех с ссылкой). Запрос идёт через Edge Function Supabase **`google-sheet-fetch`** (обход CORS).

Развернуть функцию (один раз, из корня репозитория с [Supabase CLI](https://supabase.com/docs/guides/cli)):

```bash
supabase functions deploy google-sheet-fetch --project-ref <ваш-project-ref>
```

## Вход и права редактирования

Сайт **открыт для просмотра** без пароля. Чтобы **редактировать**, нажмите **«Войти»** в шапке и введите **логин** и **пароль**. Отдельного переключателя «Просмотр / Редактирование» нет: после входа режим правок включается автоматически в пределах роли.

| Роль | Что можно |
|------|-----------|
| **Администратор** | Редактировать **весь график**, **«Объекты и состав»**, расстановку по зонам. Меню: экспорт, объекты, смена пароля, выход. |
| **Сотрудник (пилотные проекты)** | Менять отметки **только в своей строке** графика; расстановку по зонам. |
| **Сотрудник (Усть-Луга)** | График **не редактирует** (только просмотр); расстановку по зонам — после входа. |

Подробнее для пользователей: [`USER_GUIDE.md`](USER_GUIDE.md) (раздел «Вход и права»).

### Настройка в Supabase (один раз)

1. **SQL Editor** → выполните [`supabase-schema.sql`](supabase-schema.sql), затем [`supabase-auth.sql`](supabase-auth.sql).
   - В **Database → Extensions** должно быть включено **pgcrypto** (иначе вход вернёт ошибку про `crypt`).
   - Если `supabase-auth.sql` уже выполняли раньше — выполните файл **ещё раз** (обновит функцию `workwatch_login`).
2. На компьютере с Node.js в корне репозитория:
   ```bash
   npm install
   set ADMIN_PASSWORD=ВашНадёжныйПароль
   npm run seed-auth
   ```
   Скрипт собирает **всех сотрудников** из `scripts/parsed-employees-2026-h1.js` и `POSITION_BY_NAME` в `app.js`, создаёт `scripts/auth-users-seed.sql` и **`scripts/auth-credentials.txt`** (логины/пароли — **не коммитьте**).
3. Выполните **`scripts/auth-users-seed.sql`** в Supabase SQL Editor.

**Логины сотрудников:** **табельный номер** (ТН), если есть в табеле; иначе латинский ярлык из фамилии (`ivanov_i`). **Начальный пароль:** `12345678` (переменная `EMPLOYEE_DEFAULT_PASSWORD`). При первом входе сайт **обязательно предложит сменить пароль**; в шапке доступна кнопка «Сменить пароль».

Повторный seed с `SEED_RESET_PASSWORDS=0` не трогает уже выданные пароли (только ФИО и роль).

**Сменить свой пароль:** меню **«Войти»** / имя в шапке → **«Сменить пароль»** (после входа).

**Сбросить пароль сотруднику (админ):** **«Объекты и состав»** → таблица сотрудников → колонка **«Пароль»** → **«↺ 12345678»**. Учитывается **текущий ТН** в таблице (логин обновится, старый translit-логин удалится). После смены ТН нажмите сброс ещё раз.

Массовое обновление учёток после правок в выгрузке: `npm run seed-auth` → выполнить `scripts/auth-users-seed.sql` в Supabase (файл пересоздаётся, в git не коммитится).

### Защита от перебора

В [`supabase-auth.sql`](supabase-auth.sql) функция **`workwatch_login`**:

- не более **25** неудачных попыток с одного IP за **15 минут**;
- после **20** ошибок по одному логину — блокировка учётки на **30 минут**;
- небольшая задержка при неверном пароле.

Сессия в браузере (**sessionStorage**) действует **12 часов**, затем нужно войти снова.

> **Важно:** общий `payload` табеля по-прежнему доступен через REST с anon-ключом. Ограничения в интерфейсе защищают от случайных правок; для строгой серверной защиты записей нужна доработка API.

## Синхронизация с Supabase (важно для доработок)

Между браузерами шарится **общее состояние табеля** через таблицу **`tabel_state`** (REST API Supabase). Схема и комментарии: [`supabase-schema.sql`](supabase-schema.sql).

### Поведение

- При загрузке приложения вызывается **`pull`** последнего `payload` для строки с `id = global`, затем **`render()`**.
- После правок, которые меняют общие данные, вызывается **`scheduleRemotePersistDebounced()`** — через **~900 ms** выполняется **`push`** (upsert того же `payload`).

### Что входит в `payload` (уходит в облако)

- правки ячеек графика по месяцам;
- состав команд (ФИО → объект) и переименование вкладок объектов;
- переопределения ТН / должности и вручную добавленные строки;
- флаг «Показать всех» в легенде;
- расстановка по зонам (утро/вечер, месяц, объект).

### Что остаётся только в этом браузере

- выбранный месяц и вкладка объекта, фильтр легенды;
- сворачивание панелей (Сводка / Объекты / Отпуска), видимость закреплённых колонок, тема (светлая при загрузке; тёмная — только до обновления страницы после переключателя);

### Архив и «живые» месяцы

- **Редактирование** доступно только для **трёх календарных месяцев**: предыдущего, текущего и **следующего** (в селекторе они идут первыми, без отдельного заголовка). Все остальные периоды — **только просмотр** (в т.ч. push правок в Supabase для таких месяцев не выполняется из-за блокировок в коде).
- В группе **«Архив»** — только **уже прошедшие** месяцы с **марта** по декабрь года **`CURRENT_SCHEDULE_YEAR`** (без трёх «живых» и без месяцев **после текущего календарного**), плюс **`ARCHIVE_DATABASE`**. Данные из **`DATABASE`** / **`ARCHIVE_DATABASE`**; для будущих месяцев того же года **вне** окна «предыдущий — текущий — следующий» график **принудительно пустой** (импорт до наступления месяца не показывается).
- Группа **«Остаток {год} (пусто)»** — месяцы **с марта по декабрь**, которые ещё **впереди** (включая июль–декабрь с пустым `DATABASE`); только просмотр, без данных до импорта или наступления месяца.
- **Выгрузка**: для любого открытого месяца — **«Экспорт для 1С»**. JSON **`exportArchiveFullYear()`** — только **не будущие** архивные месяцы (и `ARCHIVE_DATABASE`).

**Если добавляете новое «общее» состояние** — расширьте `buildSharedPayload` / `applySharedPayload` в `app.js` и при необходимости обновите `supabase-schema.sql`.

Расширенные пометки для Cursor: [`.cursor/rules/workwatch-remote-sync.mdc`](.cursor/rules/workwatch-remote-sync.mdc).

## Карта BLE без VPN

Метки с API идут через Cloudflare Worker (`*.workers.dev`); без VPN этот домен часто блокируется.

**Без VPN карта берёт метки из файла** [`data/ble-map-cache.json`](data/ble-map-cache.json) на GitHub Pages (публикуется вместе с сайтом). Сначала грузится он (~1,4 МБ), затем в фоне — попытка обновить с API.

**Офлайн-пакет с фото для телефона** — подробная инструкция: **[`docs/ble-field-pack.md`](docs/ble-field-pack.md)** (сборка на ПК, публикация zip, meta, телефон).

**Обновить кэш меток** (нужен VPN на машине администратора): двойной щелчок [`ble-cache-push.bat`](ble-cache-push.bat) или `npm run ble-cache`. Чтобы дублировать кэш в Supabase (таблица `ble_map_cache`, сейчас может быть пустой):

```bat
set SUPABASE_SERVICE_ROLE_KEY=ваш_service_role
ble-cache-push.bat
```

**Обход API в браузере:** Edge Function **`ble-map-proxy`** (браузер → `supabase.co` → Worker). Один раз из корня репозитория с [Supabase CLI](https://supabase.com/docs/guides/cli):

```bash
supabase login
supabase link --project-ref owcuvcshwtivqueftiuk
supabase functions deploy ble-map-proxy --no-verify-jwt
```

Код: [`supabase/functions/ble-map-proxy/`](supabase/functions/ble-map-proxy/). В `ble-map.js` сначала пробуется Supabase, при ошибке — прямой Worker (как на портале обходов).

## Бэкапы базы в Supabase

Сейчас в облаке одна строка **`tabel_state`** с `id = global` и полем **`payload`** (JSON). Резервное копирование — это сохранение этого JSON (и при росте данных — дамп всей таблицы / проекта).

### Быстро из панели Supabase

1. Зайдите в [Supabase Dashboard](https://supabase.com/dashboard) → ваш проект.
2. **Table Editor** → таблица **`tabel_state`** → откройте строку `global` → скопируйте **`payload`** в файл или сделайте экспорт строки.
3. Либо **SQL Editor** → выполните выборку и сохраните результат, например:
   ```sql
   select id, payload, updated_at from public.tabel_state where id = 'global';
   ```
4. Для полного бэкапа проекта (все таблицы): **Project Settings** → **Database** → **Backups** (на платных планах есть автоматические бэкапы) или используйте **`pg_dump`** с connection string из **Settings → Database** (осторожно с секретами, не коммитьте в git).

### Вместе с кодом приложения

- Периодически сохраняйте выгрузки графика в репозиторий (`scripts/*.js`) и/или делайте **«Экспорт для 1С»** (в т.ч. для архивных месяцев) — это копии данных **на момент экспорта**, не замена серверного бэкапа.
